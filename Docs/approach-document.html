1. Executive Summary & Objective

This document details the architectural and implementation strategy devised for Client ABC Pharmacy. As a .NET Core and React.js Full Stack Developer, the objective was to craft a robust, production-ready Single Page Application (SPA) pairing an ASP.NET Core 8 Web API backend with a dynamic, component-driven React 18 user interface, featuring server-side JSON persistence.

Key Deliverables:
  • Full inventory tracking with designated business attributes.
  • Grid visualization with conditional color coding (Red for < 30d expiry, Yellow for < 10 units stock).
  • Real-time search filtering on medicine name and brand via React useMemo.
  • Integrated Point-of-Sale (POS) & sales transaction history.
  • Thread-safe JSON server-side persistence using SemaphoreSlim.
Assessment Evaluation Pillars:
  • Portability: Instant launch via standard dotnet run without needing external node/npm builds or DB services.
  • React 18 Best Practices: Functional components, custom hooks, unidirectional data flow, and declarative rendering.
  • Data Integrity: Concurrency-safe file locking & atomic stock deductions.
  • Enterprise Readiness: Clean layered architecture prepared for seamless database transition (EF Core).

2. High-Level Architectural Approach

The system employs a Decoupled Client-Server Layered Architecture. The backend acts as a stateless, RESTful API layer managing data integrity and business rules, while the frontend is a modern React 18 Single Page Application hosted directly via ASP.NET Core Static Files in wwwroot/.

Layer Component Responsibilities
Presentation (SPA) React 18 + Bootstrap 5 (Hosted in wwwroot/) Declarative UI rendering, React Hooks (useState, useEffect, useMemo), real-time color indications, instant client search, POS modals.
API & Routing ASP.NET Core 8 Controllers RESTful endpoint routing, HTTP verb dispatching, model binding, input validation (Data Annotations), CORS handling.
Business & Domain IPharmacyService & PharmacyService Inventory rules, stock deduction validation, sale pricing calculation, seed data population, concurrency serialization.
Persistence JSON Storage (medicines.json, sales.json) Server-side data persistence managed with SemaphoreSlim serialization and async file I/O.
Single-Process Zero-Friction Co-location: By configuring ASP.NET Core to serve both the Web API endpoints (/api/*) and the React 18 SPA within Kestrel, technical assessors can build and run the entire solution with a single CLI command (dotnet run), eliminating CORS hurdles, multi-process dependencies, and npm build prerequisites during evaluation.

3. Technology Selection & Design Rationale

3.1 Backend: .NET 8 Web API

  • Strong Typing & Annotations: Guarantees strict input sanitization on attributes like price formatting (2 decimals) and non-negative stock counts.
  • Asynchronous Pipeline: Built-in async/await file streaming ensures high throughput even with disk-based persistence.
  • OpenAPI / Swagger: Self-documenting API endpoints enable evaluators to inspect and test the API contract independently.

3.2 Frontend: React 18 SPA

  • Declarative Component Architecture: Functional components with React Hooks provide clean separation of concerns, eliminating spaghetti DOM code.
  • Memoized Performance (useMemo): Real-time filtering by medicine name, brand, status, and sort criteria computes efficiently without re-rendering unaffected components.
  • Industry Standard for .NET Developers: React 18 is the premier frontend framework paired with .NET enterprise backends, demonstrating industry-standard full-stack competence.
  • Zero-Build Assessor Friction: React 18 and ReactDOM are packaged locally in wwwroot/js/ with in-browser Babel compilation, allowing assessors to run the application immediately with pure dotnet run.

3.3 Persistence: JSON Store with SemaphoreSlim

  • Requirement Alignment: The assessment explicitly required server-side JSON storage.
  • Concurrency Hazard Mitigation: File-based persistence risks race conditions and corruption during concurrent writes. We implemented a SemaphoreSlim(1, 1) lock pattern inside a singleton PharmacyService to serialize read-modify-write transactions safely.

4. Functional Specification & UI Logic

4.1 Medicine Attributes Representation

Attribute Data Type Validation & Formatting Display Location
Full Name String Required, length 2–150 chars Grid column 1 (Bold)
Brand String Required, length 1–100 chars Grid column 2 (Badge)
Expiry Date Date / ISO 8601 Required, validated date Grid column 3 + Days countdown
Quantity Integer Required, range: 0 – 1,000,000 Grid column 4 (Stock badge)
Price Decimal (18,2) Required, range: 0.01 – 1,000,000.00 Grid column 5 (Currency $xx.xx)
Notes String Optional text / clinical notes Excluded from grid columns; accessible via "View Notes" action modal

4.2 Color Indication Business Rules

The system evaluates each record against the two critical operational thresholds:

Red Background (.row-expiring-soon): Applied when (ExpiryDate - Today) < 30 days. Highlights expired or critically expiring medications requiring pharmacist clearance.
Yellow Background (.row-low-stock): Applied when Quantity < 10. Alerts staff to reorder replenishable stock.
Dual Indication Handling: If a medicine satisfies both conditions (e.g., expiring in 9 days with only 4 units remaining), the row applies a prioritized dual-alert styling (.row-critical-both) with dual alert badges.

4.3 Sales Records Mechanism

The Point-of-Sale (POS) integration ensures real-time inventory integrity:

  1. User selects a medicine and inputs the desired sale quantity.
  2. Client and server validate that Quantity > 0 and Quantity ≤ AvailableStock.
  3. The system calculates TotalPrice = Math.Round(Price * Quantity, 2).
  4. Upon confirmation, medicine inventory is decremented and saved to medicines.json.
  5. A distinct immutable transaction record is written to sales.json with an ISO timestamp.
  6. React's state engine immediately re-renders the grid, dynamically updating the medicine's stock quantity and color indicators in real time.

5. Enterprise Scalability & Evolution Roadmap

For transitioning this assessment architecture to enterprise-grade pharmacy scale, the following evolution paths are designed:

  • Database Migration: Replace PharmacyService JSON storage with Entity Framework Core (EF Core) backed by PostgreSQL or Microsoft SQL Server via dependency injection without modifying API controllers.
  • Distributed Caching: Introduce Redis caching for read-heavy inventory queries.
  • Event-Driven Auditing: Emit domain events via RabbitMQ or Azure Service Bus upon sale completion for warehouse replenishment.
  • Role-Based Access Control (RBAC): Implement JWT authentication with distinct roles (e.g., Pharmacist, Cashier, Auditor).
