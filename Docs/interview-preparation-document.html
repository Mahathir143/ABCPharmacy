1. The 2-Minute Solution Walkthrough (Elevator Pitch)

When the interviewer opens with: "Tell me about this project and walk me through your technical solution", deliver this confident, structured answer:

"Thank you. As a .NET and React Full Stack Developer, I engineered this Single Page Application for Client ABC Pharmacy to streamline medicine inventory control and point-of-sale transactions with precision and high performance."

"I structured the solution around three core architectural pillars:

  1. Component-Driven React 18 UI: I implemented the frontend using modern React 18 functional components with hooks (useState, useEffect, and useMemo). I tracked all mandatory medicine attributes, excluding Notes from the main grid columns to preserve visual clarity while providing an instant modal inspection view.
  2. Proactive Visual Alerts & Instant Filtering: Leveraged React's useMemo hook to perform real-time, memoized multi-attribute search and dynamic color coding—applying soft Red for medicines expiring in under 30 days and Yellow for stock under 10 units, with a dual-warning badge for items triggering both.
  3. Thread-Safe ASP.NET Core Web API: Because the assessment required server-side JSON file persistence, I designed a thread-safe repository service utilizing SemaphoreSlim(1,1). When a sale is processed, the system atomically validates stock, deducts inventory, calculates the exact bill, and records the immutable transaction in JSON with complete concurrency protection."

"The solution is fully self-contained: evaluators can run the entire system with a single dotnet run command without external database setups or npm build friction."

2. High-Frequency Technical Interview Q&A (.NET + React)

React 18 & State Q1: Why did you use React 18 and how does the state update flow when a sale is recorded?

Answer: "React 18 is the enterprise standard for pairing with .NET Web APIs due to its declarative component model and unidirectional data flow.

When a cashier records a sale:

  1. The RecordSaleModal validates the sale quantity against available stock in local state before dispatching a POST /api/sales request.
  2. Upon receiving the 201 Created response from the Web API, React's state setter updates both the medicines array and the sales array.
  3. The useMemo hook listening to the medicines dependency immediately re-computes the filtered grid. If a medicine's stock dropped below 10, React automatically recalculates the row's CSS class to .row-low-stock (Yellow) in real time without a page refresh."
Performance Q2: Why did you choose useMemo for medicine filtering and search?

Answer: "Without useMemo, filtering, search query matching, status filtering, and multi-column sorting would execute on every single render—for example, whenever the user types a single character in a modal input, toggles a toast, or switches tabs.

By wrapping the filtering pipeline in useMemo(() => { ... }, [medicines, searchQuery, statusFilter, sortBy, sortOrder]), React caches the computed list and only re-evaluates when one of those explicit dependencies changes, drastically improving rendering performance."

Concurrency Q3: How did you solve concurrency and race conditions with server-side JSON persistence?

Answer: "In ASP.NET Core, incoming HTTP requests run concurrently across thread-pool threads. If two cashiers sell units of the same medicine simultaneously, parallel read-modify-write operations on medicines.json would cause file locking exceptions (IOException) or dirty writes resulting in negative stock.

To eliminate this, I registered PharmacyService as a Singleton and protected all file read/write operations using an asynchronous mutual-exclusion lock: SemaphoreSlim(1, 1). The semaphore guarantees that only one request enters the critical section at any given time, reading the latest JSON data, validating stock, decrementing the quantity, and writing back to disk before releasing the lock."

Architecture Q4: How would you migrate this architecture to an enterprise production environment?

Answer: "Because I designed the backend against an interface contract (IPharmacyService), scaling to enterprise scale requires zero changes to the API controllers or the React frontend:

  1. Database Transition: Implement EfPharmacyService using Entity Framework Core with SQL Server or PostgreSQL, incorporating optimistic concurrency tokens (RowVersion).
  2. Caching: Wrap frequent inventory reads in a Redis distributed cache with write-through invalidation upon sales.
  3. Asynchronous Events: Emit a MedicineSoldEvent via RabbitMQ or Azure Service Bus to trigger automatic inventory re-ordering and analytics ingestion.
  4. Security: Implement OAuth2/OpenID Connect with JWT Bearer tokens and ASP.NET Core Role-Based Authorization."
React Forms Q5: Are your forms in React controlled or uncontrolled? Why?

Answer: "I implemented Controlled Components. Every input's value is bound to React state (via value and onChange handlers). This allows live validation—for instance, disabling the sale confirmation button immediately if the entered quantity exceeds available stock, and displaying real-time bill calculations dynamically."

3. Potential Live Coding / Modification Challenges & Solutions

Assessors often ask candidates to make quick changes during the interview. Here are rapid solutions for the most common requests:

Challenge A: "Add a discount percentage field to the React sale form"

Solution: In app.js, add discountPercent: 0 to saleForm state, and update the computed total:

const saleTotalPrice = useMemo(() => {
  if (!selectedSaleMedicine || !saleForm.quantity) return '0.00';
  const gross = selectedSaleMedicine.price * saleForm.quantity;
  const discount = gross * ((Number(saleForm.discountPercent) || 0) / 100);
  return (gross - discount).toFixed(2);
}, [selectedSaleMedicine, saleForm.quantity, saleForm.discountPercent]);

Challenge B: "Export sales history as a CSV file in .NET"

Solution: Add a new endpoint to SalesController.cs:

[HttpGet("export-csv")]
public async Task<IActionResult> ExportCsv()
{
    var sales = await _pharmacyService.GetSalesAsync();
    var sb = new StringBuilder();
    sb.AppendLine("SaleId,Date,Medicine,Brand,Quantity,UnitPrice,TotalPrice");
    foreach (var s in sales)
    {
        sb.AppendLine($"{s.Id},{s.SaleDate:yyyy-MM-dd},{s.MedicineName},{s.Brand},{s.Quantity},{s.UnitPrice},{s.TotalPrice}");
    }
    return File(Encoding.UTF8.GetBytes(sb.ToString()), "text/csv", "sales.csv");
}
